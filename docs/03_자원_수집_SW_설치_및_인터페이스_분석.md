## 1. 개요

### 1.1 목적

분산된 마이크로 데이터센터(MDC)의 CPU·메모리·스토리지·네트워크·GPU·전력·온도 등
자원 상태를 실시간으로 수집하기 위한 수집 SW의 구성·설치 방법과
수집 데이터의 인터페이스(메트릭 이름, 데이터 포맷, 프로토콜)를 분석·정의한다.

### 1.2 수집 아키텍처

Prometheus 에코시스템의 Exporter(에이전트)를 활용하여 Pull 방식으로 수집한다.

```
[MDC 각 노드]                    [수집 서버]

 node_exporter  (:9100) ◀─┐
 dcgm_exporter  (:9400) ◀─┤── Prometheus (:9090)
 ipmi_exporter  (:9290) ◀─┤        │
 snmp_exporter  (:9116) ◀─┘        │ remote_write
                                    ▼
                             VictoriaMetrics (:8428)
```

| 구성요소 | 역할 | 라이선스 |
|----------|------|----------|
| **Prometheus** | 메트릭 수집 엔진 (Pull 방식), 알람 규칙 평가 | Apache 2.0 |
| **node_exporter** | 리눅스 서버 시스템 메트릭 수집 | Apache 2.0 |
| **dcgm_exporter** | NVIDIA GPU 메트릭 수집 | Apache 2.0 |
| **ipmi_exporter** | IPMI 기반 물리 서버 메트릭 (전력, 온도, 팬) | MIT |
| **snmp_exporter** | SNMP 기반 네트워크 장비/SAN 스위치 메트릭 | Apache 2.0 |
| **VictoriaMetrics** | 장기 메트릭 저장소 (Prometheus remote_write 수신) | Apache 2.0 |

## 2. 수집 SW별 설치 및 설정

### 2.1 node_exporter (서버 시스템 메트릭)

**설치 대상:** MDC 내 모든 물리/가상 서버

#### 설치

```bash
# 바이너리 다운로드 (v1.9.1)
wget https://github.com/prometheus/node_exporter/releases/download/v1.9.1/node_exporter-1.9.1.linux-amd64.tar.gz
tar xzf node_exporter-1.9.1.linux-amd64.tar.gz
sudo cp node_exporter-1.9.1.linux-amd64/node_exporter /usr/local/bin/

# systemd 서비스 등록
sudo tee /etc/systemd/system/node_exporter.service > /dev/null <<'EOF'
[Unit]
Description=Prometheus Node Exporter
After=network.target

[Service]
User=node_exporter
Group=node_exporter
Type=simple
ExecStart=/usr/local/bin/node_exporter \
  --collector.cpu \
  --collector.meminfo \
  --collector.diskstats \
  --collector.filesystem \
  --collector.netdev \
  --collector.loadavg \
  --collector.processes \
  --collector.systemd \
  --collector.systemd.unit-exclude=".+\.(automount|device|mount|scope|slice|swap|target|timer|path|socket)|(systemd|getty|snap|dbus|polkit|rsyslog|cron|user)\S*" \
  --web.listen-address=:9100

[Install]
WantedBy=multi-user.target
EOF

sudo useradd --system --no-create-home --shell /usr/sbin/nologin node_exporter
sudo systemctl daemon-reload
sudo systemctl enable --now node_exporter
```

#### 수집 확인

```bash
curl http://localhost:9100/metrics | head -30
```

#### systemd collector

`--collector.systemd`는 node_exporter 기본값이 꺼짐이다(매 scrape마다 systemd D-Bus를 조회하고 유닛 수만큼 시계열이 늘어나므로).
Confluence 원본 명세(2026-08-10)의 설치 절차에는 없고 이 문서에서 추가했다. 다음 기능이 이 collector의 `node_systemd_unit_state`에 의존한다.

| 기능 | 사용 지표 |
|------|-----------|
| 자원 탐색기 > 노드 > Service Status 패널 | `node_systemd_unit_state{name,state,type}` |
| 노드 로그/트레이스 탭 > 서비스 추가 후보 탐지(systemd 유닛 후보, docs/11 §7.3 후속) | 같은 지표의 `state="active"` |

`--collector.systemd.unit-exclude` 패턴은 기본값(`.+\.(automount|device|mount|scope|slice)`)에 swap·target·timer·path·socket 유닛과
systemd 내부·getty·snap·dbus·polkit·rsyslog·cron·user 유닛을 더해 잡음을 걸러 낸다. 관측 대상 서비스가 이 패턴에 걸리면 패턴에서 빼면 된다.

**기존 서버에서 켜기** (이미 설치된 node_exporter에 옵션만 추가할 때)

```bash
# 1. 현재 실행 인자 확인 — collector.systemd 가 없고 지표가 0건이면 꺼진 상태
systemctl cat node_exporter | grep -n -E "ExecStart|collector"; curl -s http://localhost:9100/metrics | grep -c node_systemd_unit_state

# 2. ExecStart 에 옵션 추가 (--web.listen-address=:9100 앞에 삽입)
UNIT=$(systemctl show -p FragmentPath --value node_exporter)
sed -i 's#--web.listen-address=:9100#--collector.systemd --collector.systemd.unit-exclude=".+\\.(automount|device|mount|scope|slice|swap|target|timer|path|socket)|(systemd|getty|snap|dbus|polkit|rsyslog|cron|user)\\S*" --web.listen-address=:9100#' "$UNIT"
grep -n ExecStart "$UNIT"

# 3. 재시작·확인 — active 유닛이 나열되면 성공. failed 면 journalctl -u node_exporter -n 20
systemctl daemon-reload && systemctl restart node_exporter && sleep 2 && systemctl is-active node_exporter
curl -s http://localhost:9100/metrics | grep 'node_systemd_unit_state{' | grep 'state="active"' | grep ' 1$' | head -20

# 4. Thanos 반영 확인 (30초 뒤, 수집 서버에서)
curl -s -G 'http://localhost:19192/api/v1/query' --data-urlencode 'query=count(node_systemd_unit_state{instance="localhost:9100",state="active"} == 1)'
```

재시작 사이 scrape 1회 정도가 비는 것 외에 영향은 없다.

**운영 반영 이력**

| 노드 | 일자 | 내용 |
|------|------|------|
| k8s-cp | 2026-09-29 | 기존 node_exporter(수동 설치, 기본 collector만)에 위 절차로 systemd collector 활성화. Thanos에 활성 유닛 33개 확인, Service Status 패널·후보 탐지(systemd 원천) 동작 |

### 2.3 ipmi_exporter (물리 서버 전력/온도)

**설치 대상:** 수집 서버 1대 (IPMI 대상 서버에 원격 접속)

#### 설치

```bash
wget https://github.com/prometheus-community/ipmi_exporter/releases/download/v1.9.0/ipmi_exporter-1.9.0.linux-amd64.tar.gz
tar xzf ipmi_exporter-1.9.0.linux-amd64.tar.gz
sudo cp ipmi_exporter-1.9.0.linux-amd64/ipmi_exporter /usr/local/bin/

# FreeIPMI 설치 (의존성)
sudo apt-get install -y freeipmi-tools
```

#### 설정 (/etc/ipmi_exporter/config.yml)

```yaml
modules:
  default:
    user: "admin"
    pass: "password"
    privilege: "admin"
    driver: "LAN_2_0"
    timeout: 10000
    collectors:
      - bmc
      - ipmi
      - dcmi       # 전력 소모
      - chassis
    custom_args:
      ipmi:
        - "--sdr-cache-recreate"
```

#### systemd 서비스

```bash
sudo tee /etc/systemd/system/ipmi_exporter.service > /dev/null <<'EOF'
[Unit]
Description=Prometheus IPMI Exporter
After=network.target

[Service]
User=root
Type=simple
ExecStart=/usr/local/bin/ipmi_exporter \
  --config.file=/etc/ipmi_exporter/config.yml \
  --web.listen-address=:9290

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now ipmi_exporter
```

## 4. 데이터 전송 인터페이스

### 4.1 Prometheus Exposition Format

모든 Exporter는 Prometheus Exposition Format (OpenMetrics 호환)으로 메트릭을 노출한다.

```
# HELP node_cpu_seconds_total Seconds the CPUs spent in each mode.
# TYPE node_cpu_seconds_total counter
node_cpu_seconds_total{cpu="0",mode="idle"} 123456.78
node_cpu_seconds_total{cpu="0",mode="user"} 23456.78
node_cpu_seconds_total{cpu="0",mode="system"} 12345.67
```

| 항목 | 값 |
|------|-----|
| 프로토콜 | HTTP |

## 6. 모니터링 에이전트 관리 (AIMS 요구사항 #52)

AIMS에서 각 MDC의 Exporter 배포 상태를 관리해야 한다.

### 6.1 에이전트 상태 모니터링

Prometheus의 `up` 메트릭으로 각 Exporter의 생존 여부를 확인한다.

```promql
# 전체 node_exporter 상태
up{job="mdc-nodes"}

# 다운된 에이전트 목록
up{job="mdc-nodes"} == 0
```

### 6.2 에이전트 버전 관리

| Exporter | 버전 메트릭 |
|----------|------------|
| node_exporter | `node_exporter_build_info{version="..."}` |
| dcgm_exporter | `dcgm_exporter_build_info{version="..."}` |

### 6.3 에이전트 배포 자동화

Ansible Playbook 또는 SSH 기반 원격 배포로 Exporter 설치/업데이트를 자동화한다.
AIMS Backend의 `/api/v1/monitoring/agents/deploy` API에서 트리거한다.
