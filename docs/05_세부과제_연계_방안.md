## 2. 인증 연계 구조

AIMS(세부2)가 **중앙 인증 서버** 역할을 하며, 세부1·3은 AIMS에서 발급한 JWT 토큰으로 인증한다.

```
[세부1 MDC]                [세부2 AIMS 포탈]              [세부3 서비스]

                      ┌──────────────────────┐
                      │   AIMS Backend       │
  토큰 검증 요청 ────▶ │   /api/v1/auth/      │ ◀──── 토큰 검증 요청
                      │   validate           │
                      │                      │
  API Key 검증 ──────▶ │   /api/v1/auth/      │ ◀──── 로그인 요청
                      │   validate-key       │
                      │                      │
                      │   JWT 발급/검증       │
                      │   사용자/역할 관리     │
                      └──────────────────────┘
```

## 3. 연계 방식별 상세

### 3.1 사용자 인증 (JWT) — 세부3 사용자

세부3의 사용자가 서비스를 배포하거나 자원을 사용할 때 AIMS 인증을 거친다.

**흐름:**

```
1. 사용자가 AIMS 포탈에서 로그인
   POST /api/v1/auth/login
   {"email": "user@sub3.org", "password": "..."}

2. AIMS가 JWT 토큰 발급
   → accessToken (30분), refreshToken (7일)

3. 세부3 시스템이 AIMS API 호출 시 토큰 포함
   Authorization: Bearer eyJhbGciOi...

4. AIMS Backend가 토큰 검증 → 권한 확인 → 처리
```

**세부3 시스템이 직접 토큰을 검증해야 하는 경우:**

```
POST /api/v1/auth/validate
{"token": "eyJhbGciOi..."}

→ 응답:
{
  "valid": true,
  "email": "user@sub3.org",
  "userId": 5,
  "name": "홍길동",
  "roles": "USER",
  "organization": "세부3기관"
}
```

### 3.2 서비스 간 통신 (API Key) — 세부1 MDC

세부1의 MDC 관리 시스템과 AIMS 간 서버 대 서버 통신에는 API Key를 사용한다.
사용자 로그인 없이 시스템 간 인증이 가능하다.

**API Key 발급 (AIMS 관리자):**

```
AIMS 관리자가 세부1용 API Key를 발급
→ API Key: "a1b2c3d4e5f6..."
→ 세부1 담당자에게 안전하게 전달
```

**세부1 → AIMS 호출 시:**

```
GET /api/v1/monitoring/resources/realtime?mdcId=mdc-01
X-API-Key: a1b2c3d4e5f6...
```

**API Key 검증 API:**

```
POST /api/v1/auth/validate-key
{"apiKey": "a1b2c3d4e5f6..."}

→ 응답:
{"valid": true}
```

### 3.3 세부1 MDC 자원 접근

AIMS 포탈에서 세부1이 구축한 MDC의 자원을 조회/제어하는 방식.

```
AIMS 포탈 사용자
    │
    │ JWT 인증된 요청
    ▼
AIMS Backend
    │
    ├── MDC 모니터링 (Prometheus/VictoriaMetrics)
    │   GET /api/v1/monitoring/resources/realtime?mdcId=mdc-01
    │
    ├── MDC 물리 서버 (IPMI)
    │   GET /api/v1/monitoring/physical/{serverId}
    │
    └── 퍼블릭 클라우드 (Cloud-Barista)
        GET /api/v1/vms?connectionName=aws-conn
```

**세부1이 해야 할 것:**
- MDC 서버에 node_exporter 설치 (포트 9100)
- GPU 서버에 dcgm_exporter 설치 (포트 9400)
- AIMS에 MDC 수집 대상 등록 (POST /api/v1/monitoring/agents)
- Prometheus scrape 대상에 MDC 노드 IP 추가

## 4. API 요약 (세부과제 연동용)

### 4.1 인증 API (인증 없이 접근 가능)

| Method | URL | 용도 | 사용 주체 |
|--------|-----|------|----------|
| POST | `/api/v1/auth/login` | 로그인, JWT 발급 | 세부3 사용자 |
| POST | `/api/v1/auth/register` | 회원가입 | 세부3 사용자 |
| POST | `/api/v1/auth/validate` | JWT 토큰 검증 | 세부1, 세부3 시스템 |
| POST | `/api/v1/auth/refresh` | Access Token 갱신 | 세부3 사용자 |
| POST | `/api/v1/auth/validate-key` | API Key 검증 | 세부1 시스템 |

### 4.2 사용자/역할 API (JWT 인증 필요)

| Method | URL | 용도 |
|--------|-----|------|
| GET | `/api/v1/users` | 사용자 목록 |
| POST | `/api/v1/users` | 사용자 생성 (관리자) |
| GET | `/api/v1/users/{id}` | 사용자 상세 |
| PUT | `/api/v1/users/{id}` | 사용자 수정 |
| DELETE | `/api/v1/users/{id}` | 사용자 삭제 |
| PATCH | `/api/v1/users/{id}/status` | 상태 변경 (활성/비활성) |
| POST | `/api/v1/users/{id}/roles/{roleId}` | 역할 할당 |
| DELETE | `/api/v1/users/{id}/roles/{roleId}` | 역할 해제 |
| GET | `/api/v1/roles` | 역할 목록 |
| POST | `/api/v1/roles` | 역할 생성 |
| POST | `/api/v1/roles/{id}/permissions` | 권한 추가 |
| GET | `/api/v1/roles/{id}/permissions` | 권한 조회 |

### 4.3 전체 API 명세 (Swagger UI)

## 6. 연동 테스트 방법

### 6.1 로그인 테스트

```bash
curl -X POST http://101.79.72.52:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@aims.cloud","password":"<비밀번호>"}'
```

응답:
```json
{
  "success": true,
  "data": {
    "accessToken": "eyJhbGciOi...",
    "refreshToken": "eyJhbGciOi..."
  }
}
```

### 6.2 인증된 API 호출

```bash
curl http://101.79.72.52:8080/api/v1/users \
  -H "Authorization: Bearer eyJhbGciOi..."
```

### 6.3 토큰 검증 (세부1,3)

```bash
curl -X POST http://101.79.72.52:8080/api/v1/auth/validate \
  -H "Content-Type: application/json" \
  -d '{"token":"eyJhbGciOi..."}'
```
