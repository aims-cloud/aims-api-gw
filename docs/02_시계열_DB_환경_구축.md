## 1. 개요

### 1.1 목적

AIMS Cloud 포탈에서 세부1(MDC), 세부2(AIMS), 세부3(서비스)의 Prometheus 메트릭을
중앙에서 수집·저장·조회하기 위한 시계열 DB 환경을 구축한다.

### 1.2 설계 원칙

- **Thanos 기반 통합 수집**: 각 세부과제의 Prometheus가 remote_write로 데이터를 전송하면 Thanos Receive가 수신
- **장기 저장**: MinIO(S3 호환) 오브젝트 저장소에 장기 보존, 자동 다운샘플링
- **단일 쿼리 인터페이스**: Thanos Query가 PromQL API를 제공하여 AIMS Backend가 세부1+2+3 데이터를 통합 조회

### 1.3 변경 이력

| 버전 | 변경 내용 |
|------|----------|
| v0.1 | VictoriaMetrics + TimescaleDB 이중 구조 |
| v0.2 | TimescaleDB 제거, VictoriaMetrics + PostgreSQL 단순화 |
| v0.3 | **VictoriaMetrics → Thanos 전환 (세부1,3 Prometheus 통합 수집 합의)** |

## 2. 아키텍처

### 2.1 전체 구성도

```
[세부1 MDC]                    [세부2 AIMS - 중앙]                   [세부3 서비스]

세부1 Prometheus               ┌──────────────────────────┐          세부3 Prometheus
     │                         │                          │               │
     │ remote_write             │   Thanos Receive         │               │ remote_write
     └────────────────────────▶│   (:19291)               │◀──────────────┘
                               │        │                 │
                               │        ▼                 │
                               │   Thanos Query           │
                               │   (:19192)               │◀─── AIMS Backend (PromQL 쿼리)
                               │        │                 │
                               │   Thanos Store Gateway   │
                               │        │                 │
                               │   MinIO (S3)             │
                               │   (:9000)                │
                               │        │                 │
                               │   Thanos Compactor       │
                               │   (다운샘플링/정리)       │
                               │                          │
                               │   Grafana (:3000)        │
                               │   PostgreSQL (빌링 집계)  │
                               └──────────────────────────┘
```

### 2.2 Thanos 컴포넌트 역할

| 컴포넌트 | 포트 | 역할 |
|----------|------|------|
| **Thanos Receive** | 19291 | 세부1,2,3 Prometheus의 remote_write 수신 |
| **Thanos Query** | 19192 | PromQL API 제공 (AIMS Backend가 사용) |
| **Thanos Store Gateway** | 10905 | MinIO에 저장된 과거 데이터 조회 |
| **Thanos Compactor** | - | 오래된 데이터 다운샘플링 및 정리 |
| **MinIO** | 9000/9001 | S3 호환 오브젝트 저장소 (장기 보존) |
| **Prometheus** | 9090 | 로컬 수집 (세부2 자체 MDC가 있는 경우) |
| **Grafana** | 3000 | 시각화 대시보드 |

### 2.3 데이터 보존 정책

Thanos Compactor가 자동으로 다운샘플링 및 삭제를 수행한다.

| 해상도 | 보존 기간 | 설명 |
|--------|----------|------|
| 원본 (raw) | 30일 | 수집된 원본 그대로 |
| 5분 평균 | 90일 | 5분 단위로 다운샘플링 |
| 1시간 평균 | 365일 | 1시간 단위로 다운샘플링 |

## 3. 설치 및 환경 구축

### 3.1 사전 준비

구축 대상 서버에 Docker와 Docker Compose가 설치되어 있어야 한다.

```bash
docker --version       # Docker 확인
docker compose version # Compose 확인
```

### 3.2 파일 구성

```
deploy/monitoring/
├── docker-compose.monitoring.yml   # 전체 스택 Compose
├── thanos-bucket.yml               # Thanos → MinIO 연결 설정
└── prometheus.yml                  # Prometheus 수집 설정
```

### 3.3 시작

```bash
cd deploy/monitoring
docker compose -f docker-compose.monitoring.yml up -d
```

### 3.4 상태 확인

```bash
# 컨테이너 상태
docker compose -f docker-compose.monitoring.yml ps

# Thanos Query 헬스체크
curl -s http://localhost:19192/-/healthy

# Thanos Receive 헬스체크
curl -s http://localhost:10902/-/healthy

# MinIO 콘솔
# 브라우저: http://localhost:9001 (${MINIO_USER} / ${MINIO_PASSWORD})

# Grafana
# 브라우저: http://localhost:3000 (admin / admin)
```

### 3.5 종료

```bash
docker compose -f docker-compose.monitoring.yml down
```

## 4. 세부과제별 연동 방법

### 4.1 세부1 (MDC) — Prometheus remote_write 설정

세부1의 prometheus.yml에 아래 2줄만 추가하면 데이터가 자동으로 AIMS로 전송된다.

```yaml
remote_write:
  - url: "http://{AIMS서버IP}:19291/api/v1/receive"
```

**세부1이 보내는 데이터 예시:**
- node_exporter: CPU, 메모리, 디스크, 네트워크
- dcgm_exporter: GPU 사용률, 온도, 전력
- ipmi_exporter: 서버 전력, 온도, 팬 속도

### 4.2 세부3 (서비스) — Prometheus remote_write 설정

세부3도 동일하게 설정한다.

```yaml
remote_write:
  - url: "http://{AIMS서버IP}:19291/api/v1/receive"
```

### 4.3 세부2 (AIMS) — 로컬 Prometheus

우리(세부2)가 자체 MDC를 운영하는 경우, 로컬 Prometheus도 동일하게 Thanos Receive로 전송한다.
Docker Compose에 포함된 Prometheus가 이 역할을 한다.

## 5. AIMS Backend 연동

### 5.1 쿼리 엔드포인트

AIMS Backend는 **Thanos Query** (:19192)에 PromQL 쿼리를 보낸다.
API가 Prometheus와 100% 호환이므로 기존 코드 변경 없이 URL만 변경하면 된다.

```yaml
# application.yml
victoria-metrics:
  base-url: ${METRICS_QUERY_URL}   # Thanos Query 주소

# application-local.yml
victoria-metrics:
  base-url: http://localhost:19192  # Thanos Query 로컬
```

### 5.2 쿼리 예시

```java
// AIMS Backend에서 Thanos Query 조회 (기존 코드 그대로 동작)
// Thanos가 세부1+2+3의 데이터를 모두 통합하여 응답한다
String promQL = "avg by(mdc_id) (100 - irate(node_cpu_seconds_total{mode='idle'}[5m]) * 100)";
// → 세부1의 MDC, 세부2의 MDC, 세부3의 서비스 메트릭이 모두 포함된 결과
```

### 5.3 세부과제별 데이터 구분

각 세부과제의 Prometheus가 레이블을 붙여 전송하면, Thanos Query에서 필터링할 수 있다.

```promql
# 세부1 MDC만 조회
node_cpu_seconds_total{sub_project="sub1"}

# 세부3 서비스만 조회
node_cpu_seconds_total{sub_project="sub3"}

# 전체 통합 조회
node_cpu_seconds_total
```

세부1,3의 Prometheus에 `external_labels`를 설정해달라고 요청한다:

```yaml
# 세부1 prometheus.yml
global:
  external_labels:
    sub_project: "sub1"
    mdc_id: "mdc-01"

# 세부3 prometheus.yml
global:
  external_labels:
    sub_project: "sub3"
```

### 5.4 빌링 집계 (PostgreSQL)

Thanos Query에서 조회한 데이터를 매시간 PostgreSQL로 집계하는 구조는 동일하다.

```
Thanos Query (PromQL) → MeteringAggregationService → metering_hourly (PostgreSQL)
```

## 8. 운영 가이드

### 8.1 일상 운영

| 작업 | 빈도 | 방법 |
|------|------|------|
| 세부과제 Prometheus 추가 | 수시 | 세부과제가 remote_write URL만 설정하면 자동 |
| 데이터 보존 기간 변경 | 드물게 | Compactor의 retention 플래그 변경 후 재시작 |
| 빌링 집계 데이터 정리 | 자동 | AIMS Backend @Scheduled 배치 (13개월 이전 삭제) |
| 장애 확인 | 수시 | Thanos Query, Receive 헬스체크 |

### 8.2 백업

| 대상 | 방법 |
|------|------|
| MinIO (메트릭 데이터) | MinIO 복제(mirror) 또는 볼륨 스냅샷 |
| PostgreSQL (빌링 집계) | pg_dump / pg_basebackup |
| 설정 파일 | Git 저장소에서 관리 |

### 8.3 용량 추정

| 항목 | 값 |
|------|-----|
| 세부과제 수 | 3개 |
| 총 Prometheus 인스턴스 | 3~5개 |
| 예상 시계열 수 | 10,000~50,000 |
| 일간 원본 데이터 | ~1GB (압축 후) |
| 연간 저장 (다운샘플링 후) | ~50GB |

MinIO에 100GB 이상의 저장 공간을 확보하면 1년 이상 운영 가능하다.
